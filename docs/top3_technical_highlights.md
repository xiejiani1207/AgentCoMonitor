# top3_technical_highlights.md

答辩最值得重点讲的 3 个技术点。

## 亮点 1：零侵入的跨 Agent 执行监控

**名称：** 零侵入适配器 + 标准化 Trace 采集

**解决的问题：** 多 Agent 系统执行过程黑盒，且监控代码不应侵入业务 Demo。

**我的实现：** 定义框架无关的 `TraceRecord` 标准模型，用 `LangGraphCallback` 通过 `astream_events` 采集每个 Agent 的起止时间、输入输出、耗时、token、父子关系，形成可复用的监控中间件。Demo 端零侵入（不 import 监控代码）。

**为什么这样设计：** 换任何 Agent 框架/业务场景，只需换适配器，监控平台不动。

**代码证据：** `agent_monitor/adapters/langgraph.py`、`agent_monitor/core/models.py`（TraceRecord）

**答辩一句话：** 用一个零侵入的适配器，把任意 Agent 框架的执行过程统一成标准 Trace，监控平台不绑定具体业务。

## 亮点 2：规则 + LLM-as-Judge 的双层质量评价

**名称：** 三层异常检测 + 五维质量评估

**解决的问题：** 如何判断 Agent 输出"好不好"，既要快又要准。

**我的实现：** 异常检测分三层（执行/行为/输出）规则扫描；质量评估五维度（合规 30%、准确 25%、完整 20%、相关 15%、时效 10%），先用规则快速过滤，再用 LLM-as-Judge 对准确性和相关性做语义打分（并行化）。

**为什么这样设计：** 纯规则快但漏语义问题，纯 LLM 慢且贵，两层结合兼顾速度与深度。

**代码证据：** `agent_monitor/core/anomaly.py`、`core/quality.py`

**答辩一句话：** 用"规则快速过滤 + LLM 语义打分"两层评价，既保证速度，又能识别语义层面的质量问题。

## 亮点 3：候选结果筛选 + 自动反馈闭环

**名称：** 多候选排序推荐 + 自我优化闭环

**解决的问题：** LLM 第一次生成的结果不可信，且人工调优成本高。

**我的实现：** 三个并行决策 Agent 产出候选建议，走"异常过滤 → 质量排序 → 去重 → 推荐"四步选出最优；对不达标的维度自动生成反馈指令，写入动态指令库并回灌进 Agent 提示词，下次执行自动优化（全自动、可回溯）。

**为什么这样设计：** 比"单个答案"更可信；比"人工逐步调优"更自动。

**代码证据：** `agent_monitor/core/optimizer.py`、`core/feedback.py`、`demo_advisory/graph.py`（3 个并行决策 Agent）

**答辩一句话：** 不直接相信第一次生成——三个候选排序择优，不达标还能自动反馈回灌、自我优化，全程无需人工介入。
