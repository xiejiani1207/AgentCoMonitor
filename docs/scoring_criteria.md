# 评分标准明细（答辩备查）

> 所有数值均来自代码，可在 `agent_monitor/core/` 下核对。阈值为设计时设定的规则值，非实验标定。

## 一、质量评估：五维度评分标准

| 维度 | 权重 | 评分方式 | 具体标准 |
|------|:---:|------|------|
| 合规性 | 30% | 敏感词库规则扫描 | 每命中 1 个敏感词扣 50 分，最低 0（1 违规=50 不合格，2+=0） |
| 准确性 | 25% | LLM-as-Judge | LLM 打 0–100 分；失败回退规则（80 起步，>100 字 +10，>500 字 +10，封顶 100） |
| 完整性 | 20% | 规则检查 | 100 起步；<50 字 -30；无"建议/结论/分析" -30；最低 0 |
| 相关性 | 15% | LLM-as-Judge | LLM 打 0–100 分；失败回退规则（重叠率 >0.3=100，>0.1=80，否则 60，无内容=50） |
| 时效性 | 10% | 规则检查 | 有日期=100；有"近期/最新/今年"等=80；无时间信息不扣分=100 |

**综合分** = Σ(维度分 × 权重) / Σ(权重)，只对有分数的维度加权。

## 二、句级合规检测（标红/拦截）

- 敏感词库默认 10 个词（Dashboard 可增删）
- 输出按 `。！？` 切句，逐句匹配
- 每命中 1 句扣 50 分（1 句=50，2+ 句=0）
- 命中句整句标红 + 拦截移除 + 记录"已拦截该说法"

## 三、异常检测：三层阈值

| 层 | 规则 | 严重度 |
|------|------|:---:|
| 执行层 | 状态=error；或 状态=timeout / 耗时 > 30000ms | 高 |
| 行为层 | 相同输入重复调用；tool_name 缺失；缺失关键 Agent | 高 |
| 输出层 | 输出空或 < 10 字 | 中 |

## 四、结果筛选优化：四步 + 阈值

1. 异常过滤：剔除 anomaly_count > 0 的候选
2. 质量排序：按综合分降序
3. 去重：相似度 > 0.95 只保留最高分
4. 推荐：第 1 名=采纳，2–3 名=备选，其余=存档

## 五、反馈/建议阈值

- 优化建议：维度分 < 70 生成（双通道）
- 反馈闭环：维度分 < 75 自动生成指令回灌

## 六、合规 LLM 审查（语义兜底）

独立 LLM 审查决策输出，打 0–100 分，抓"换说法"的违规。

## 诚实口径

这些阈值是**设计时的启发式规则**（业务直觉：合规是金融硬约束，权重最高、违规直接不合格），**不是实验标定的**。老师若问"为什么扣 50 不是别的数"，答：规则层为了"有违规就亮红灯"边界清晰、可解释；要更严谨需基于标注数据标定。
