# 演示视频脚本

分场景演示脚本，每个场景配「操作步骤 + 解说词」，总时长约 5-6 分钟。

## 录制前准备

1. 启动三个服务（监控 8000 / 投顾 8001 / 前端 3000）
2. 数据库迁移到 002（`alembic upgrade head`）
3. 建议清空旧数据，让概览页干净（可选）
4. 准备录屏软件，浏览器打开 `http://localhost:3000`，先停在「智能投顾」页

---

## 场景 1：开场（~30s）

**操作**：镜头对着电脑，切到项目 README 或 Dashboard 首页。

**解说词**：
> 大家好，这是「跨智能体协同执行智能监控与结果筛选优化系统」。多智能体系统现在很流行，但 Agent 到底执行得对不对、好不好，往往还靠人肉去 Review。我这个项目做了一套**自动化的监控平台**——让系统自己盯着 Agent 干活，发现输出不达标时，还能**自动反馈**让它自我修正。下面我完整演示一遍。

---

## 场景 2：架构一句话（~20s，可选）

**操作**：切到 `docs/design.md` 的架构图。

**解说词**：
> 系统分两块：一个是领域无关的通用监控平台，一个是用来验证的金融投顾 Demo。中间通过一个「适配器」零侵入地对接——Demo 完全不知道自己在被监控。这是一个多轮对话的投顾助手，由 6 个 Agent 协作完成分析。

---

## 场景 3：单轮问答 + 实时监控（~1min，核心）

**操作**：在「智能投顾」输入「分析 600519 贵州茅台」，点发送。

**解说词**：
> 我输入一个问题——分析贵州茅台。注意看下方这六个步骤条：数据采集、技术面、基本面、风控、决策、合规，它们是**实时逐个点亮**的，因为监控平台通过 WebSocket 实时采集了每个 Agent 的执行状态。

（等报告出来）

> 结果出来了。上面是最终输出，中间是技术面、基本面、风控、决策、合规五段完整分析报告，下面是「监控质检」——监控平台给每个 Agent 打了质量分，还有合规性、异常、优化建议。也就是说，**业务在跑的同时，监控已经在背后质检了**。

---

## 场景 4：多轮对话 + 记忆 Agent（~30s）

**操作**：继续输入「那风险大不大？」（不带股票代码），发送。

**解说词**：
> 关键来了——我故意**不写股票代码**，只问一句"那风险大不大？"。系统通过一个**记忆 Agent** 理解上下文，自动补全到刚才的贵州茅台，而不是报错说"没找到股票"。这就是多轮对话里的上下文管理。

---

## 场景 5：演示模式 + 检测能力（~1min）

**操作**：打开「演示模式」开关，再发一条查询。

**解说词**：
> 平时这些 Agent 因为有合规约束，输出都是合规的。为了演示监控的"抓错"能力，我打开**演示模式**——人为注入两个破绽：让决策 Agent 说"保证收益、稳赚不赔"，再让技术面 Agent 超时。

（等结果）

> 看，顶部出现了橙色的"演示模式"横幅，说明这是人为注入、不是造假。再看监控质检：合规分掉下来了（不再是满分），异常数也变成了非零。监控平台**同时**抓到了合规违规和超时异常。

---

## 场景 6：监控 Dashboard（~1min）

**操作**：切到「异常告警」页，再切「链路追踪」，选一个任务。

**解说词**：
> 切到监控 Dashboard 的「异常告警」页，刚才注入的超时异常在这里出现了，有级别、有类型、有处理建议。再看「链路追踪」——这是刚才那次执行的真实拓扑图，6 个 Agent 谁先谁后、谁是并行分支，一目了然。回到「概览总览」，每次执行的任务、状态、高危告警都在这里统计。

---

## 场景 7：反馈闭环（~40s，最大亮点）

**操作**：切回 chat 结果，滚动到「监控质检」底部的「反馈闭环」区块。

**解说词**：
> 这是整个项目**最核心的亮点**——反馈闭环。监控平台识别到问题后，不是只把告警丢给人看，而是**自动**生成了反馈指令，比如"决策 Agent 要遵守合规要求"、"技术面 Agent 要保证执行可靠"，并且已经**自动回灌**给了投顾系统。

（可选：打开数据库查 agent_instructions 表）

> 这些指令已经写进了动态指令库。下次再执行时，它们会自动注入到对应 Agent 的提示词里——**系统在自我修正，全程没有人工介入**。

---

## 场景 8：总结（~30s）

**操作**：切回 README 或空白页，镜头回人。

**解说词**：
> 总结一下：这是一套"能盯着 Agent 干活、还能帮 Agent 改作业"的监控系统。三大能力——实时监控采集、三层异常检测 + 五维质量评估、以及**自动反馈闭环**。整个原型用 FastAPI + LangGraph + React 搭建，配套了完整的软件工程文档和 CI。谢谢大家，欢迎提问。

---

## 录制小贴士

1. **总时长控制在 5-6 分钟**，每个场景别拖。
2. **场景 3 和 5 是重点**（实时监控 + 检测能力），可以多给镜头。
3. **场景 7 一定要讲清楚**（反馈闭环是创新点），甚至可以配一句"这就是自动化和人工 Review 的区别"。
4. 录的时候把浏览器缩放调大、字体放大，让导师看清步骤条和质量分。
5. 如果担心 LLM 慢（单次 ~27s），录制时可以**提前跑一轮**，把结果留在页面上，正式录时直接展示，避免干等。
