# 用户使用说明

## 1. 系统简介

AgentCoMonitor 是一套**跨智能体协同执行的智能监控与结果筛选优化系统**：监控平台自动观察多智能体系统的执行过程，检测异常、评估质量、筛选优化结果，并在识别到输出不达标时**自动反馈**给被监控系统，实现自我优化闭环。Demo 以「金融投顾」场景验证：一个 6-Agent 的 LangGraph 投顾链路，支持多轮对话。

## 2. 安装

```bash
git clone https://github.com/xiejiani1207/AgentCoMonitor.git
cd AgentCoMonitor
cp .env.example .env              # 填入 Neon DB 连接串 + AM_LLM_* / DEMO_LLM_* key
pip install -e ".[dev]"
cd dashboard && npm install && cd ..
alembic upgrade head              # 初始化数据库
```

## 3. 启动（三个终端）

```bash
# 终端 1：监控服务（:8000）
uvicorn agent_monitor.api.main:app --reload

# 终端 2：投顾服务（:8001）
uvicorn demo_service.main:app --port 8001

# 终端 3：前端（:3000，重启以加载代理规则）
cd dashboard && npm run dev
```

浏览器打开 `http://localhost:3000`。

## 4. 功能使用

### 4.1 智能投顾（多轮对话）
1. 导航栏点「智能投顾」。
2. 输入框输入查询，如「分析 600519 贵州茅台」，或点示例 chip，点「发送」。
3. 观察步骤条 6 个 Agent（数据采集→技术面/基本面→风控→决策→合规）**逐个变绿**。
4. 报告展示：最终输出 + 折叠的「分析报告」+「监控质检」徽章（综合质量/合规/异常/建议 + 各 Agent 质量分 + 反馈闭环指令）。
5. **多轮追问**：继续输入「那风险大不大？」，系统靠记忆 Agent 自动补全到 600519。

### 4.2 演示模式（注入破绽）
打开输入框上方的「演示模式」开关后发送，系统会人为注入合规违规 + 超时异常，用于确定性演示反馈闭环。结果顶部会显示橙色「演示模式」横幅（透明标注）。

### 4.3 监控 Dashboard
- **概览总览**：任务统计（总数/已完成/失败/高危告警）+ 最近任务表 + 最近告警表。
- **链路追踪**：下拉选择一个任务，查看 6 个 Agent 的 DAG 拓扑图。
- **异常告警**：告警列表（级别/类型/层级/描述/建议），支持级别筛选，WebSocket 实时刷新。
- **任务详情**：点击概览页任务行进入，查看各 Agent 的输入/输出/质量评分时间线。

### 4.4 反馈闭环（自动）
每次 chat 跑完后，监控服务自动生成反馈指令并回灌 demo，无需人工介入。可在 chat 结果的「监控质检 → 反馈闭环」区块看到本次生成了哪些指令；下次执行时这些指令会自动注入到对应 Agent 的 System Prompt。

## 5. 完整演示流程

1. 启动三个服务。
2. 打开「智能投顾」，输入「分析 600519 贵州茅台」→ 看步骤条 + 报告 + 监控质检。
3. 追问「那风险大不大？」→ 看记忆 Agent 解析上下文。
4. 打开「演示模式」再发一条 → 看橙色横幅 + 合规分下降 + 异常出现。
5. 切到「异常告警」页 → 看到 timeout 告警。
6. 切到「链路追踪」→ 选任务看 DAG。
7. 切回 chat 结果的「反馈闭环」区块 → 看到自动生成的反馈指令。

**一句话概括**：用户多轮对话提问 → 6 Agent 协同分析 → 监控实时质检 → 自动反馈回灌 → 自我优化，全程无人工介入。

## 7. 常见问题

**Q1：前端时间显示差 8 小时？**
后端存的是 naive UTC，前端 `formatTime` 已按 UTC 解析再转本地，确保已重启前端。

**Q2：chat 返回 405？**
API 路径（`/advisory`）与页面路由（`/chat`）分离后已修复，确保前端重启加载代理规则。

**Q3：反馈闭环没触发？**
需三个服务都在运行（尤其监控服务）。若监控服务未启动，chat 会静默跳过反馈（不报错）。

**Q4：数据库指令文本都一样？**
这是设计如此——指令文本是预设模板，**触发检测是智能的**（识别哪个维度低）。这是为了演示的确定性。

**Q5：多轮对话刷新后失效？**
当前对话历史存在前端状态，刷新即失。持久化属可选优化（见 task_plan.md Backlog）。
