# 需求规格说明书

## 1. 引言

### 1.1 目的
本文档定义「跨智能体协同执行智能监控与结果筛选优化系统」（AgentCoMonitor）的功能需求与非功能需求，作为设计与验收的依据。

### 1.2 背景
多智能体协同任务（Multi-Agent）在金融、电商等领域逐步落地，但 Agent 的执行日志、决策链路、异常行为与输出质量仍主要依赖人工 Review 校验，成本高、时效差。本系统构建一套**自动化智能监控与结果筛选优化平台**，实现"系统自动盯着 Agent 干活"，并在识别到输出不达标时**自动反馈**给被监控系统，形成自我优化闭环。

### 1.3 范围
- **Part 1：通用监控平台** —— 领域无关、框架无关的监控中间件。
- **Part 2：金融投顾 Demo** —— 被监控的业务对象，用于验证平台能力。

### 1.4 术语
| 术语 | 说明 |
|------|------|
| Trace | 一次 Agent 执行的标准化记录 |
| TraceRecord | 框架无关的通用 Trace 数据模型 |
| LLM-as-Judge | 用 LLM 对输出内容进行语义质量打分 |
| 适配器（Adapter） | 将框架原生事件转换为 TraceRecord 的桥接层 |
| 反馈闭环 | 监控平台识别问题 → 自动反馈指令 → 被监控系统自我调整 |

## 2. 用户角色

| 角色 | 说明 |
|------|------|
| 系统管理员/开发者 | 部署、配置、维护监控平台与 Demo |
| 业务用户 | 通过投顾 Demo 与多智能体系统交互（问答） |
| 监控运维人员 | 通过 Dashboard 观察 Agent 执行状态、处理告警 |
| 导师/评审 | 通过文档与演示验收系统 |

## 3. 功能需求

### FR-1 执行监控采集
系统应能通过框架适配器**零侵入**地采集每个 Agent 的执行数据（输入、输出、起止时间、耗时、token 用量、状态、父子关系），并标准化为 TraceRecord 持久化。

### FR-2 异常检测
系统应能对 Trace 进行**三层扫描**：
- 执行层：超时、执行失败、Token 飙升；
- 行为层：循环调用、关键节点缺失、无效工具调用；
- 输出层：空输出、过短输出。

按 high / medium / low 三级告警。

### FR-3 输出质量评估
系统应能对 Agent 输出进行**五维度打分**（合规性、准确性、完整性、相关性、时效性，0-100 分），支持「规则快速过滤 + LLM-as-Judge 语义评估」两层策略，并加权计算综合分。

### FR-4 结果筛选优化
系统应能对多条结果执行「异常过滤 → 质量排序 → 多样性去重 → 推荐」，并生成**双通道优化建议**（人类可读建议 + Agent 结构化指令）。

### FR-5 监控可视化 Dashboard
系统应提供 Web Dashboard，包含：
- 概览总览：任务统计、健康度、最近告警；
- 链路追踪：Agent 执行 DAG 拓扑图（含并行分支）；
- 任务详情：时间线、输入输出、质量评分、优化建议；
- 异常告警：告警列表、级别筛选、处理建议。
并支持 WebSocket 实时推送。

### FR-6 金融投顾 Demo
系统应提供一个基于 LangGraph 的 6-Agent 投顾链路（数据采集 → 技术面 ∥ 基本面 → 风控 → 决策 → 合规），使用真实 A 股历史数据（5 只股票，60 天日线）。

### FR-7 多轮对话
Demo 应支持多轮对话：用户可追问（如"那风险大不大？"），系统通过**记忆 Agent** 解析省略指代、维护上下文。

### FR-8 反馈闭环（自我优化）
监控平台识别到输出不达标（合规违规 / 高危异常 / 质量分低于阈值）时，应**自动**生成反馈指令，通过 HTTP 推送至投顾服务；投顾服务将指令存入**动态指令库**，并在后续执行时自动注入到 Agent 的 System Prompt，实现无人工介入的自我优化。

### FR-9 演示模式
系统应提供「演示模式」开关，可人为注入合规违规与超时异常，用于确定性演示反馈闭环（需透明标注）。

## 4. 非功能需求

| 编号 | 需求 | 说明 |
|------|------|------|
| NFR-1 性能 | 单次 Demo 链路在可接受时间内完成 | 经优化后约 27s（graph 串行 LLM 为固有成本） |
| NFR-2 可靠性 | LLM 服务异常时自动降级 | 规则层兜底，LLM-as-Judge 失败时回退默认分 |
| NFR-3 可维护性 | 模块化、框架无关 | 适配器模式解耦，换 Demo 场景不动监控代码 |
| NFR-4 安全性 | 敏感信息不入库/不入 git | `.env`（DB 密码、API Key）gitignore |
| NFR-5 可测试性 | CI 全绿 | 25 个单元/集成测试 + ruff lint |
| NFR-6 可移植性 | 一键部署 | `pip install -e .` + `alembic upgrade head` + 3 服务启动 |

## 5. 约束

1. 数据库迁移只通过 Alembic，不手改 schema。
2. Demo 零侵入：`demo_advisory/` 不 import `agent_monitor`。
3. 监控平台与 Demo 的 LLM 密钥分离（`AM_LLM_*` 与 `DEMO_LLM_*`）。
4. Push 前必须 `ruff check` + `pytest` 全绿。

## 6. 验收标准

1. 投顾 Demo 全链路可运行，6 个 Agent 产出完整报告。
2. 监控平台能实时采集 Trace、检测异常、评估质量、生成建议。
3. Dashboard 能可视化展示任务、拓扑、告警。
4. 反馈闭环可自动触发，指令能回灌并影响后续执行。
5. 多轮对话能正确解析上下文。
6. 全部测试通过，CI 全绿。
